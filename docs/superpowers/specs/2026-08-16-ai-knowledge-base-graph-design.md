# Veridian AI 知识库 & 知识图谱 —— 总体设计 / 路线图

日期:2026-08-16
状态:愿景已对齐,待逐期细化 spec

---

## 1. 愿景

Veridian 的 AI 不只是"从库里找答案",而是**帮你构建这个库**:把导入的论文自动读成结构化笔记,在论文/笔记之间建立带类型的链接,连成一张可导航的知识图谱。**读与写是同一个助手的两只手**;知识库随文献导入**自动生长**,而非人工逐条喂养。

参照系是**通用研究助手**(DeepSeek 式:能读、会写、能联网、会推理),**不是**编程 agent——因此不涉及子代理、MCP、终端等开发向能力。

关键转变:**笔记从"论文的附属"升级为知识库的一等公民**(可独立存在、可 `[[双链]]`、可成为图谱节点)。

---

## 2. 现状盘点(基于代码事实)

**已具备**
- AI 助手:工具循环 agent(`src/main/knowledge/agent.ts`,MAX_ROUNDS=8),只读工具 `search_library` / `get_item_info` / `read_context`,技能渐进披露 `load_skill`。
- 检索:`hybridSearch` = FTS5 + 向量 KNN → RRF → 重排;跨语言查询翻译;scope 过滤。
- 索引流水线(`src/main/knowledge/indexer.ts`,事件驱动):`attachment.changed` → 去抖 `scanAndIndex()` → Phase1 `ensureChunks`(分块 + FTS,按 content-hash 幂等)→ Phase2 `embedPending`(向量嵌入,失败保持 pending 重试)。进度经 `job.progress` 事件上报。
- 数据表(`src/main/db/index.ts`):`items` / `collections` / `collection_items` / `tags` / `item_tags` / `attachments` / `notes`。
- 元数据补全:`crossref.ts`、`MetadataService`(已存在,尚未包成 AI 工具)。
- @提及(论文/文件/技能)、停止/重生成/编辑重发、检索过程可视化(`RetrievalTrace`)。

**缺失(本设计要补)**
- AI 只读,**不能对库做任何写操作**(打标签、加分类、建笔记、补元数据都做不了)。
- 笔记只能挂在论文下(`notes.item_id NOT NULL`),**无独立笔记、无笔记类型**。
- **无条目间链接**:没有 relations/edges 表,没有 `[[wikilink]]`,没有反向链接。
- **无图谱可视化**。
- AI 看不到库的组织结构(分类、标签清单),够不到本地库以外(联网检索/补全未成工具)。

---

## 3. 架构:流水线为脊

自动解读作为索引流水线的 **Phase3**,挂在 `ensureChunks` 之后,复用现有"后台跑 / content-hash 幂等 / 未配置就跳过 / 失败 pending 重试 / job.progress 进度"的成熟模式:

```
导入 PDF → MinerU → Full.md
   └─ attachment.changed → indexer.scanAndIndex()
        ├─ Phase1 ensureChunks   分块 + FTS
        ├─ Phase2 embedPending   向量嵌入
        └─ Phase3【新增·AI 解读】← 本设计
             ├─ 质量闸(正文字数/文本占比;不足则跳过)
             ├─ 生成结构化摘要笔记
             ├─ 抽取概念 → 标签
             ├─ 语义搜库内相关条目 → 候选链接 → 判断关系类型
             └─ 分级落库(见 §6)
```

**核心洞察:自动解读不是新造逻辑,而是"自动调用 P1 的写能力"。** 手动时聊天 agent 调 `create_note`/`link_items`/`add_tag`;自动时导入流水线调同一批工具。**P1 给"手",P4 让手在导入时自己动。**

## 4. 数据模型变更

1. **笔记升为一等公民**
   - `notes.item_id` 改为可空(`NULL` = 独立笔记),新增 `title`、`updated_by`(`ai`/`user`,用于保护人工编辑,见 §7 情况 7)、`analysis_hash`(源论文内容哈希,用于幂等)。
   - 独立笔记在中栏条目列表可见、可筛选。
2. **关系表 `relations`(图谱的边)**
   - `id, workspace_id, src_kind('item'|'note'), src_id, dst_kind, dst_id, rel_type, origin('ai'|'user'), created_at`。
   - `rel_type` 取固定小集合:`扩展 / 矛盾 / 同主题 / 引用 / 方法相同`(可后续增补)。
   - `ON DELETE CASCADE`:源/目标被删则边清理。
3. **AI 建议队列 `suggestions`(分级落库的审核暂存)**
   - `id, workspace_id, kind('link'|...), payload(JSON), status('pending'|'accepted'|'rejected'), created_at`。
   - 自动落库的项(摘要笔记、标签)不进此表;进审核队列的项(链接)在此等确认。
4. **解读状态**:`items` 增列或旁表记录 `analysis_state`(`未解读/解读中/已解读/跳过/失败`)+ `analysis_hash`。

所有迁移遵循现有"幂等追加式"约定。

## 6. 自动解读流程(P4)

**产出三样(具体形态)**
- **① 摘要笔记**:AI 读全文后写的结构化卡片(一句话概括 / 研究问题 / 方法 / 主要发现[带数据] / 贡献与局限 / 关键概念),存入 `notes`,挂在该论文下,`updated_by='ai'`。
- **② 标签**:全文抽取的主题词,写入 `item_tags`。
- **③ 链接**:语义搜库内相关条目,建立带类型的边,写入 `relations`。

**分级落库(已锁定)**
- ① 摘要笔记、② 标签 → **自动落库**(只影响本篇,错了删掉即可,无副作用)。
- ③ 链接 → **进审核队列 `suggestions`**(会改变整张图谱形状,值得人扫一眼再确认)。

**触发(已锁定倾向)**
- **默认开启、后台自动**:每次导入转 markdown 后自动后台解读;设置可关。
- 另提供"**批量解读存量文献**"动作处理已有库;大批量(> N 篇)先弹确认预估成本。

**语言**:笔记默认与论文正文同语言(可后续做成配置)。

## 7. 失败与边缘情况处理

原则:解读阶段永远"尽力而为、可跳过、可重试、幂等",**绝不阻塞导入本身,绝不因失败写坏数据**。每篇论文都有诚实的解读状态。

| # | 情况 | 处理 |
|---|---|---|
| 1 | 转 markdown 失败 | 不触发解读;条目标 `未解读·转换失败`,可见 + "重试转换"。可选 pdf-parse 纯文本兜底。 |
| 2 | 扫描件/空 markdown | 质量闸:正文不足则跳过,标 `文本不足,已跳过`,不耗 token。 |
| 3 | 解读 LLM 调用失败 | 指数退避重试;保持 pending,下次扫描重试;不阻塞其他论文。 |
| 4 | LLM 返回格式错 | zod 校验;重试 1 次仍失败则跳过标 `解读失败`,不写垃圾。 |
| 5 | 模型未配置 | 整阶段静默跳过(仿嵌入 FTS-only)。 |
| 6 | 重复导入/markdown 更新 | 按 `analysis_hash` 幂等:未变跳过;变了更新原笔记、重评标签/链接,不生成第二条笔记。 |
| 7 | 用户改过 AI 笔记又重导 | `updated_by='user'` 的笔记不覆盖(或另存版本),保护人工成果。 |
| 8 | 条目被删/回收 | `relations`、AI 笔记、待审链接全部 CASCADE 清理,无悬空边。 |
| 9 | 库太小无可链接对象 | 正常,链接建议为空。 |
| 10 | 超长论文超上下文 | 分块 map-reduce 摘要或取关键章节;设 token 上限。 |
| 11 | 批量导入成本失控 | 队列 + 并发上限 + 进度;大批量先确认预估。 |

## 8. UI 结合方式

哲学:**只给"全局图谱"新开一块整屏画布;其余(笔记、关联、AI 解读、审核队列)全部织进现有三栏 + 详情标签**——用户不学新 App,知识库是 Veridian 的自然延伸。

```
┌─────────────────────────────────────────────────────────────┐
│ 工具栏                                        [库][知识图谱★] │
├──────────┬────────────────────┬─────────────────────────────┤
│ 左栏      │  中栏:条目列表      │  右栏:详情(标签页)         │
│ 分类树    │  论文 + 笔记(可筛) │  [信息][附件]               │
│  ├分类A   │                    │  [AI解读★]  摘要笔记卡片      │
│  ├分类B   │                    │  [关联/反链★] relations+反链 │
│ ─────     │                    │  [局部图谱★] 该条目一跳邻居  │
│ 📝 笔记★  │                    │                             │
│ 🕸 图谱★  │                    │                             │
│ 📥 待审关联★(n)                 │                             │
└──────────┴────────────────────┴─────────────────────────────┘
                       ★ = 新增
```

- **全局知识图谱**:顶层视图,主区域整屏切换(与"库"互斥,像切 Tab),**按当前工作区隔离**。节点 = 论文 + 笔记,边 = relations;标签/分类作着色/聚类维度。点节点→高亮邻居 + 侧边简介;双击→跳回"库"并选中;支持缩放/拖拽/搜索定位。
- **局部图谱**:详情页标签,仅选中条目的一跳邻居(轻量,可先于全局图上线)。
- **AI 解读**:详情页标签,展示摘要笔记卡片。
- **关联/反链**:详情页标签,列出连出/连入的边(带关系类型),点击跳转。
- **待审关联**:左栏带角标收件箱,汇总进审核队列的链接,逐条通过/驳回。
- **AI 聊天页**:保留,获得写能力;图谱节点右键可"就此与 AI 讨论"。

## 9. 分期路线

每期各自 spec → plan → 实现;**P1 先做**(手动与自动共用的底座)。

| 期 | 范围 | 依赖 |
|---|---|---|
| **P1** | 写能力地基:一等公民笔记 + `relations`/`suggestions` 表 + 写工具(create_note/edit_note/add_tag/add_to_collection/**link_items**/update_metadata/star)+ 结构感知读工具(list_collections/list_tags/read_notes)+ 动作审批 | 现有 schema |
| **P2** | 双链 `[[ ]]` 解析 + 反向链接;crossref/arXiv 包成 AI 联网工具 | P1 |
| **P3** | 图谱可视化(全局整屏视图 + 局部图谱标签) | P1(边数据)/P2 |
| **P4** | 自动解读流水线(indexer Phase3,编排 P1 工具,分级落库 + 失败处理 + 批量存量) | P1 |

---

## 10. 已锁定的决策

1. 先做 P1(写能力),参照系为通用研究助手而非编程 agent。
2. 笔记升为一等公民(可独立、可双链、可成图谱节点)。
3. 自动解读产出分级落库:摘要笔记 + 标签自动,链接进审核队列。
4. 自动解读后台自动 + 配开关 + 批量存量动作;默认姿态(默认开 vs 首次询问)暂定"默认开",待 P4 spec 最终确认。
5. 图谱:全局整屏新视图 + 详情页局部图谱标签,按工作区隔离;其余 KB 内容织进现有三栏/详情标签。
6. 失败处理:解读阶段尽力而为、可跳过/重试/幂等,不阻塞导入、不写坏数据。

## 11. 待后续各期 spec 细化的开放项

- 摘要笔记模板字段是否可配置(v1 固定)。
- `rel_type` 关系类型的最终取值集合与可扩展方式。
- 审批交互的具体形态(逐条 / 批量 / 快捷键)。
- 图谱布局算法与大规模(数千节点)性能策略。
- 触发默认姿态最终确认(默认开 vs 首次询问)——本设计暂定默认开。
- 联网工具的数据源与合规边界(Crossref/arXiv/其他)。
